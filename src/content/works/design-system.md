## 概要

3つの小売ブランドの EC・会員アプリ・店舗向けツールで共通利用できるデザインシステムを、ゼロから設計・構築しました。ブランドの個性を保ちながら、開発の土台を1つにすることが目標でした。

## 課題

- 同じ「ボタン」がブランドごと・画面ごとに20種類以上存在し、デザインと実装の差分確認に毎回時間を取られていた
- ブランドごとに異なるフレームワーク（React / Vue / 素の HTML）が使われていた
- アクセシビリティの基準がなく、コントラスト不足やキーボード操作不可の箇所が多数あった

## 担当範囲

既存UIの棚卸し、デザイントークンの設計、Figma ライブラリの構築、Web Components による実装、ドキュメントサイトの制作、各チームへの導入支援を担当しました。

## プロセス

1. **棚卸しと原則づくり** — 約400画面をキャプチャして分類し、重複と不整合を可視化しました。そのうえで「判断を減らす」「誰でも使える」「ブランドは表層で表現する」という3原則を定めています。
2. **3階層のトークン** — プリミティブ・セマンティック・コンポーネントの3階層でトークンを設計し、ブランドの差分をセマンティック層の差し替えだけで表現できるようにしました。Style Dictionary で Figma と CSS 変数を同期しています。
3. **フレームワークに依存しない実装** — 各チームの技術スタックを問わず使えるよう、Lit による Web Components で実装しました。全コンポーネントが WCAG 2.2 AA を満たすことを、CI 上の自動テストで担保しています。
4. **採用を促す仕組み** — 使い方とアンチパターンを並べたドキュメントサイトを用意し、隔週の「デザインシステム相談会」で現場の要望を吸い上げる体制を作りました。

## 結果と今後

新規画面のUI実装工数は 35% 削減し、axe による自動検出のアクセシビリティ違反は 92% 減少しました。共通コンポーネントは 120 種類を超え、現在は先方チームが自走して運用しています。
