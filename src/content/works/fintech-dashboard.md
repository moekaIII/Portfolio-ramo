#### 概要

法人向け資産管理SaaSの中核であるダッシュボードを、情報設計・UI・フロントエンド実装まで一貫して刷新したプロジェクトです。経理担当者が毎朝最初に開く画面でありながら、表示の遅さと情報の多さが慢性的な不満になっていました。

#### 課題

- 初期表示に平均4秒以上かかり、「重い」という声がサポート問い合わせの上位を占めていた
- 機能追加のたびにウィジェットが積み重なり、本当に見るべき数値が埋もれていた
- 旧来の jQuery 資産と新規 React 画面が混在し、改修コストが高止まりしていた

#### 担当範囲

ユーザーインタビューの設計と実施、情報設計、UIデザイン、フロントエンドのアーキテクチャ設計と実装、パフォーマンス計測の仕組みづくりまでを担当しました。バックエンドは先方エンジニア2名と API 仕様を共同で策定しています。

#### プロセス

1. **計測から始める** — RUM（Real User Monitoring）を導入し、どの指標がどの端末で悪化しているかを可視化しました。遅さの主因は、初期描画時に全ウィジェットのデータを直列で取得していたことでした。
2. **「朝の5分」に絞った情報設計** — 担当者12名へのインタビューから、朝の確認作業で見る指標は平均3つに収束することが分かりました。ファーストビューをその3指標と推移グラフに絞り、残りは詳細ビューへ段階的に開示しています。
3. **段階的な移行** — SvelteKit でダッシュボードを新規構築し、既存画面とはルーティング単位で共存させました。ストリーミングSSRとデータ取得の並列化により、体感速度を大きく改善しています。
4. **品質の自動化** — Storybook でのビジュアルリグレッションと、Playwright による Web Vitals の継続計測を CI に組み込み、性能の劣化をマージ前に検知できるようにしました。

#### 結果と今後

LCP は 4.1秒 から 1.3秒 に改善し、主要タスクの完了時間は 42% 短縮しました。リリース後3か月の月次解約率は 18% 低下し、営業資料でも「速さ」が訴求ポイントとして使われるようになっています。
