#### 概要

5つのWebサービスで、フレームワーク・ビルド設定・コード規約がそれぞれ異なっていた組織に、共通のフロントエンド開発基盤を導入しました。技術選定から、モノレポ構成、CI/CD、開発ルールの策定と定着までを担当しています。

#### 課題

- サービスごとに技術スタックが異なり、異動や応援のたびに立ち上がりに時間がかかっていた
- 同じ UI や処理を各サービスで個別に実装しており、品質にばらつきがあった
- レビュー基準がなく、レビュー待ちが開発のボトルネックになっていた

#### 取り組み

1. **技術選定** — 既存資産・チームのスキル・運用コストを比較表にまとめ、関係者と合意しながら標準スタックを決定しました。
2. **モノレポと共通パッケージ** — pnpm workspace で UI コンポーネント・設定・ユーティリティを共通化し、各サービスから同じ版を使えるようにしました。
3. **CI/CD とテスト** — 型チェック・Lint・テスト・ビジュアルリグレッションを PR ごとに自動実行し、レビューでは設計と仕様に集中できるようにしました。
4. **組織への定着** — 開発ガイドラインと ADR（設計判断の記録）を整備し、週次の勉強会で運用を浸透させました。

#### 結果と今後

新規画面の立ち上げにかかる時間が短くなり、サービス間の人の行き来もスムーズになりました。現在は共通パッケージの拡充と、デザインシステムとの連携を進めています。
