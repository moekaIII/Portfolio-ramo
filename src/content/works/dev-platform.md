#### 概要

参画当初、チームには JavaScript フレームワークを活用した開発基盤が存在しませんでした。導入を提案したところ、チームリーダーから正式に依頼をいただき、技術選定から基盤構築、運用の仕組み化まで一貫して担当しました。

#### 課題

- JavaScript フレームワークを使った開発基盤がなく、コンポーネントやノウハウが個人ごとに蓄積されていた
- フレームワークの経験者が少なく、導入時の学習コストが大きな壁になっていた
- 1サイトあたり大量の画像を扱うため、画像の軽量化やサイズ指定を手作業で行う負担が大きかった

#### 取り組み

1. **技術選定** — 経験者が少ないチームの状況を踏まえ、学習コストと必要な機能の実現性を考慮して Svelte を採用しました。
2. **学習コストを下げる実装** — 汎用的なコンポーネントを拡充し、細部まで他のメンバーの使いやすさを考えて実装することで、導入時の負担を軽減しました。
3. **画像処理の自動化** — 従来手作業で行っていた画像の軽量化やサイズ指定を自動化するため、SvelteKit の Enhanced Image を活用した独自コンポーネントを開発しました。チームが抱える画像管理上の課題や要望を整理し、AI も活用しながら試行錯誤を重ねることで、実際の制作フローに適した仕組みを実現しています。
4. **継続的な運用フロー** — 基盤を構築して終わりにするのではなく、進化し続けるフロントエンド技術やチームのレギュレーションに合わせて改善を続けられるよう、GitHub を次のように活用しました。
   - **Issue / Milestone** — 改善提案・課題提起
   - **Wiki** — 運用フローの定義・周知
   - **GitHub Actions** — バージョンのタグ付け・リリースバージョン更新の自動化
5. **定着の推進** — メンバーへの導入・運用面でのフォローも担い、チーム全体への定着を進めました。

#### 結果

- チームの定例会議で基盤について話し合う時間が設けられ、個人に蓄積されていたコンポーネントやノウハウを、チーム全体の資産として共有・成長させる流れができました。
- 手作業で行っていた実装・運用業務の多くを自動化し、開発効率と知識の再利用性の向上に貢献しました。
- 2025年10月、この取り組みと成果が評価され、全社のベストエンジニア賞を受賞しました。
